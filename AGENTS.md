# Project Instructions

- Start with the relevant app root: this repository has Vite/React apps at the workspace root and under `Frontend/`. Check that app's `package.json`, `index.html`, and `vite.config.js` before changing or running it; do not assume the two trees are interchangeable.
- The ASP.NET Core 8 API is in `Backend/`. Controllers define HTTP endpoints, services hold domain operations, and `Backend/Data/AppDbContext.cs` maps MySQL entities. Follow the established boundary and DTO conventions rather than putting persistence logic in controllers.
- Frontend API calls are under `src/api/` (or the matching app's `src/api/`). Check `apiConfig.js`, `VITE_API_BASE_URL`, Vite middleware, and the corresponding backend route when tracing a request. Local UI state, browser storage, `server-db.json`, and the MySQL database are distinct persistence paths; verify the path actually used before claiming a write reached the database.
- Backend startup expects MySQL `DefaultConnection` and JWT configuration and listens on port 5018. `Backend/Data/DbInitializer.cs` performs schema setup and seeds data; inspect its effects and use a disposable database before running it against data that must be preserved.
- Keep credentials and connection strings out of source control and chat output. Use local environment/configuration files without copying their secret values into instructions or logs.
- Use the root package scripts for the root frontend: `npm run dev`, `npm run build`, and `npm run lint`. For `Frontend/`, run the same scripts from that directory. Backend commands from the workspace root: `dotnet build Backend/HMS.csproj` and `dotnet run --project Backend/HMS.csproj`.
- No dedicated backend unit-test project is evident. `Backend/test_e2e.cjs` requires a running API and configured database and creates/deletes records; inspect its targets and effects before running it.
- Prefer the existing documentation over duplicating API or schema details: [README.md](README.md), [Swagger API testing](Backend/Documentation/HMS_POS_SWAGGER_TESTING.md), [API comparison](Backend/Documentation/HMS_POS_API_COMPARISON.md), and [database updates](Backend/Documentation/HMS_POS_DATABASE_UPDATES.sql).
